# Lean PRD: 월별 요약

- 상태: 계획 / 미착수
- 구현 브랜치: `feature/monthly-summary`
- 선행 기준: [전체 PRD](PRD.md), [공통 CLI 보완](PRD-002.md), [거래 CRUD](PRD-001.md)

## 1. 목적

특정 달의 총 수입·지출·잔액과 지출이 큰 카테고리를 확인할 수 있도록 한다.
거래 파일을 한 번 순회해 집계하며 전체 거래를 메모리에 보관하지 않는다.

## 2. 범위

### 포함

- `summary` 명령의 월 지정과 카테고리 지출 TOP N
- 총 수입·총 지출·잔액 출력
- 거래가 없는 달과 지출이 없는 달의 명확한 안내
- 제너레이터 기반 단일 순회 집계

### 제외

- 연간·주간 요약, 날짜 범위 요약, 차트, 별도 리포트 파일 저장
- 예산 계산·표시: [PRD-006](PRD-006.md)에서 연동

## 3. 사용자 시나리오

옵션 접두사는 [전체 PRD의 확인 사항](PRD.md#5-cli-표기-확인-사항)에 따른다.
아래 예시는 기존 `--` 표기를 사용한 초안이다.

```zsh
python -m budget_app summary --month 2026-09
python -m budget_app summary --month 2026-09 --top 5
python -m budget_app summary --help
```

`--month`는 필수이며 `--top`을 생략하면 3개 카테고리를 출력한다.
출력에는 조회 월과 다음 항목을 포함한다.

```text
2026-09 월별 요약
총 수입: 3000000원
총 지출: 215000원
잔액: 2785000원
지출 TOP 3
1) rent 150000원
2) food 45000원
3) transport 20000원
```

월별 거래가 없으면 “데이터 없음”과 수입·지출·잔액 0원을 표시한다.
지출이 없으면 TOP 목록 대신 “지출 없음”을 표시한다. 수입만 있는 달도 같은 규칙을 따른다.

## 4. 데이터 모델

기존 `Transaction`의 날짜·타입·금액·카테고리를 집계에 사용한다.
요약 결과는 지정 월, 거래 건수, 수입 합계, 지출 합계, 카테고리별 지출 합계를 담는
타입이 명시된 결과 구조로 표현한다. 새 영구 저장 모델은 필요하지 않다.

- 총 수입: 해당 월 `income` 거래의 금액 합계
- 총 지출: 해당 월 `expense` 거래의 금액 합계
- 잔액: 총 수입 - 총 지출이며 음수도 허용
- 카테고리별 지출: 해당 월 `expense`만 이름별 합산
- TOP 정렬: 지출 합계 내림차순, 동률이면 카테고리 이름 오름차순

이름 정렬은 Python 문자열 기본 정렬을 사용하며 별도 언어별 정렬을 적용하지 않는다.

## 5. 저장 방식

- 공통 데이터 폴더의 `transactions.jsonl`을 읽기만 한다.
- 거래 저장 순서에 관계없이 거래 날짜의 연·월로 대상 달을 판별한다.
- `TransactionRepository.iter_all()` 제너레이터를 한 번 순회한다.
- 메모리에는 합계·건수·카테고리별 합계만 유지한다.
- 전체 거래를 리스트로 만들거나 정렬하지 않는다. TOP 정렬은 집계된 카테고리에만 적용한다.

## 6. 구조

- `cli.py`: 필수 월·선택 TOP 옵션, 요약 결과 출력
- `validators.py`: `YYYY-MM` 검증 및 TOP 양수 정수 변환
- `services.py`: 월 필터·단일 순회 합산·카테고리 순위 계산
- `models.py`: 필요한 경우 타입이 명시된 요약 결과 구조 정의
- `repositories.py`: 기존 거래 제너레이터 재사용

공통 데이터 경로와 오류·종료 코드 정책은 PRD-002를 따른다.
예산 연동에 필요한 총 지출 값은 PRD-006이 계산 결과에서 재사용한다.

## 7. 주요 검증 규칙

- 월은 정확히 `YYYY-MM` 형식이며 실제 달력의 연도·월이어야 한다.
- `2026-9`, `2026-00`, `2026-13`, `0000-01`은 거부한다.
- 월을 생략하면 사용법과 해결 힌트를 출력하고 오류 종료한다.
- TOP은 0보다 큰 정수이며 0·음수·소수·문자열은 거부한다.
- 지출 카테고리가 N개보다 적으면 실제 존재하는 카테고리만 출력한다.
- 소수 금액이나 반올림 없이 기존 양수 정수 금액을 그대로 합산한다.

## 8. 완료 조건

표준 라이브러리 `unittest`로 다음 수용 사례를 검증한다.

| 사례 | 기대 결과 |
| --- | --- |
| 여러 달의 수입·지출이 혼재 | 지정 월 거래만 수입·지출·잔액에 포함 |
| 월 첫날·말일과 인접 월 거래 | 해당 달의 경계 거래만 포함 |
| 같은 카테고리의 여러 지출 | 하나의 합계로 집계하고 수입은 제외 |
| 지출 합계가 같은 카테고리 | 이름 오름차순으로 순위 고정 |
| TOP 생략 / 카테고리 수보다 큰 TOP | 기본 3개 / 실제 카테고리만 표시 |
| 거래 없는 달 / 수입만 있는 달 | 각각 데이터 없음·0원 / 정상 수입·0원 지출 |
| 총 지출이 수입보다 큰 달 | 음수 잔액을 정확히 출력 |
| 잘못된 월·TOP 또는 필수 월 생략 | 오류·해결 힌트, 비정상 종료 코드 |
| 다시 순회할 수 없는 거래 제너레이터 | 한 번 순회만으로 정확한 결과 생성 |

조회 후 저장 파일이 유지되는지 확인한다.
관련 테스트와 전체 테스트, Ruff 포맷·검사를 통과하고 README·PROGRESS를 갱신한다.

## 9. 구현 순서

1. 월·TOP 검증과 요약 결과 구조를 정의한다.
2. 기존 거래 제너레이터를 사용하는 집계 서비스를 구현한다.
3. CLI 출력과 빈 결과 안내를 연결한다.
4. 수용 사례 및 회귀 테스트를 실행하고 문서를 갱신한다.
