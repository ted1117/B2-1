# Lean PRD: 거래 검색

- 브랜치: `feature/transaction-search`
- 상태: 계획 / 구현 미착수
- 선행 작업: [PRD-002](PRD-002.md), [PRD-003](PRD-003.md)
- 공통 기준: [전체 PRD](PRD.md)

## 1. 목적

저장된 거래를 기간·카테고리·타입·메모·태그로 검색한다. 거래 수가 늘어나도
파일이나 결과 전체를 메모리에 적재하지 않고 최신순으로 출력한다.

## 2. 범위

### 포함

- `search` 명령과 6개 검색 옵션
- 조건 결합, 기간 검증, 빈 결과 처리
- 등록 역순 제너레이터와 조건 필터
- CSV 내보내기에서도 재사용할 날짜 범위 판정

### 제외

정규식·유사 검색, OR 조건, 페이지 기능, 새 정렬 옵션, 검색 결과 파일 저장은
추가하지 않는다.

## 3. 사용자 시나리오

```text
python -m budget_app search -from 2026-09-01 -to 2026-09-30
python -m budget_app search -category food -type expense
python -m budget_app search -q 점심 -tag meal
```

옵션 접두사는 [공통 CLI 표기](PRD.md#5-cli-표기)를 따른다.

| 옵션 이름 | 비교 방식 |
| --- | --- |
| `from` | 거래일이 시작일 이상 |
| `to` | 거래일이 종료일 이하 |
| `category` | 등록된 카테고리 이름과 정확히 일치 |
| `type` | `income` 또는 `expense`와 일치 |
| `q` | 메모에 키워드가 포함됨, 대소문자 구분 |
| `tag` | 태그 목록의 항목과 정확히 일치, 대소문자 구분 |

모든 옵션은 선택이고 함께 지정하면 AND 조건이다. 날짜 한쪽만 지정하는
검색을 허용한다. 아무 조건도 없으면 전체 거래를 스트리밍 출력한다.
메모 키워드는 태그·카테고리에 적용하지 않는다. 빈 문자열·공백만 입력한
검색어·태그·카테고리는 유효하지 않은 입력으로 처리한다.

결과는 `list`와 같은 거래 표시 형식으로 등록 역순 출력한다. 일치하는 거래가
없으면 `검색 결과 없음`을 출력하고 정상 종료한다.

## 4. 구조 및 스트리밍

저장소는 등록 역순의 `Iterator[Transaction]`을 제공하고, 서비스는 이를
순회하며 조건을 만족하는 거래만 `yield`한다. CLI는 결과를 즉시 출력한다.

최신순은 거래 날짜 정렬이 아닌 파일 저장 순서의 역순이다. 고정 크기 블록으로
파일 끝에서부터 읽고 완성된 줄을 UTF-8로 해석하는 방식 등을 사용한다.
블록 경계를 가로지르는 한글·긴 줄·마지막 개행이 없는 파일을 올바르게 처리한다.
메모리 사용은 블록과 한 거래의 크기에 비례하며 전체 거래 수에 비례하지 않는다.

`list()`·무제한 `deque`·전체 정렬 후 반환은 완료로 인정하지 않는다. 기존
정방향 `iter_all()`과 CRUD의 저장 형식·순서는 유지한다. 날짜 조건 판정은
서비스/검증 계층에 두어 PRD-007에서도 동일한 규칙을 적용한다.

## 5. 검증 규칙

- 날짜는 실제 달력 날짜이며 `YYYY-MM-DD` 형식이어야 한다.
- 시작일이 종료일보다 뒤이면 오류다. 양 끝 날짜는 결과에 포함한다.
- 허용되지 않은 타입·미등록 카테고리는 원인과 해결 힌트를 출력한다.
- 저장 파일의 손상된 행을 조용히 생략하지 않고 PRD-002의 오류 규칙을 따른다.
- 검색은 JSONL 파일을 수정하지 않는다.

## 6. 완료 조건

- [ ] 날짜·카테고리·타입·메모·태그를 각각 단독으로 검색할 수 있다.
- [ ] 여섯 조건을 함께 주면 모두 만족하는 거래만 출력한다.
- [ ] 기간 경계 포함, 시작일만·종료일만, 역전 범위 오류가 검증된다.
- [ ] `meal` 태그 검색에 `meal-time`만 있는 거래는 포함되지 않는다.
- [ ] 과거 날짜를 나중에 등록한 거래도 등록 순서에 따라 먼저 출력한다.
- [ ] 조건 없음·일치 없음·빈 저장 파일이 정의된 결과와 코드로 종료한다.
- [ ] 한글 블록 경계·긴 JSONL 행·빈 줄·마지막 개행 없는 파일을 처리한다.
- [ ] 제너레이터 반환뿐 아니라 실제 파일 읽기도 블록/행 단위인지 확인한다.
- [ ] 반환 결과 전체를 리스트에 모으지 않는지 코드 및 대량 파일 실행으로 확인한다.
- [ ] 도움말·README 예시·관련 `unittest`·전체 테스트·Ruff가 통과한다.

## 7. 구현 순서

1. 날짜 범위·문자열 검색 조건 검증을 작성한다.
2. 저장소에 역순 스트리밍 읽기를 추가한다.
3. 서비스의 제너레이터 필터와 CLI를 연결한다.
4. 조건 조합·순서·파일 경계 사례를 검증한다.
5. 전체 검사 후 README·PROGRESS를 갱신한다.
