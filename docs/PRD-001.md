# Lean PRD: Transaction 기능

## 1. 목적

가계부 프로그램의 핵심 데이터인 거래(Transaction)를 생성, 조회, 수정, 삭제할 수 있도록 한다.

이 브랜치에서는 거래 데이터의 기본 모델과 파일 저장 구조를 만들고, CLI를 통해 거래 CRUD가 동작하는 최소 기능을 구현한다.

---

## 2. 범위

### 포함

- `Transaction` 데이터 모델 정의
- 거래 데이터 JSONL 저장
- 거래 추가
- 거래 목록 조회
- 거래 수정
- 거래 삭제
- 거래 ID 생성
- JSONL 데이터를 제너레이터 기반으로 조회
- 거래 입력값 기본 검증
- 거래 추가 시 등록된 카테고리 확인
- 미등록 카테고리 안내 및 등록 또는 재입력 흐름
- 카테고리 이름 JSONL 저장
- CLI에서 거래 관련 명령 실행

### 제외

다음 기능은 다른 브랜치에서 구현한다.

- 거래 검색
- 월별 요약
- 카테고리 이름 수정·삭제 및 별도 관리 명령
- 예산 관리
- CSV import/export
- 공통 데코레이터
- 전역 예외 처리 구조

## 3. 사용자 시나리오

### 거래 추가

사용자는 다음 명령을 실행한다.

```zsh
python -m budget_app add
```

프로그램은 다음 값을 순서대로 입력받는다.

- 날짜
- 타입
- 카테고리
- 금액
- 메모
- 태그

입력값이 유효하면 거래를 저장하고 생성된 ID를 출력한다.

입력한 카테고리가 등록된 목록에 없으면 현재 등록된 카테고리를 안내한다.
사용자는 입력한 이름을 새 카테고리로 등록하거나 카테고리를 다시 입력한다.
카테고리가 등록되거나 기존 목록에서 확인된 경우에만 거래 추가를 계속한다.

예:

```text
[저장 완료] id=TX-000001
```

---

### 거래 목록 조회

사용자는 다음 명령을 실행한다.

```zsh
python -m budget_app list
```

또는 조회 개수를 지정한다.

```zsh
python -m budget_app list -limit 10
```

저장된 거래를 최신순으로 출력한다.

파일 전체를 `list`로 한 번에 읽지 않고 제너레이터를 사용한다.

---

### 거래 수정

수정 방식은 옵션 기반으로 고정한다.

```zsh
python -m budget_app update \
  -id TX-000001 \
  -amount 15000 \
  -memo "저녁"
```

지정되지 않은 필드는 기존 값을 유지한다.

존재하지 않는 ID인 경우 수정하지 않고 오류 메시지를 출력한다.

---

### 거래 삭제

사용자는 다음 명령을 실행한다.

```zsh
python -m budget_app delete -id TX-000001
```

해당 거래가 존재하면 삭제한다.

존재하지 않는 ID라면 오류 메시지를 출력한다.

## 4. 데이터 모델

거래는 `dataclass`로 정의한다.

```python
Transaction
├── id: str
├── type: str
├── date: date
├── amount: int
├── category: str
├── memo: str
└── tags: list[str]
```

### 필드 규칙

- `id`

  - 유일해야 한다.
  - 형식 예: `TX-000001`
- `type`

  - `income` 또는 `expense`
- `date`

  - 입력 형식은 `YYYY-MM-DD`
  - 프로그램 내부에서는 `datetime.date` 사용
- `amount`

  - 0보다 큰 정수
- `category`

  - 비어 있지 않은 문자열
  - 거래 추가 시 등록된 카테고리 목록에 존재해야 한다.
- `memo`

  - 선택값
- `tags`

  - 0개 이상의 문자열

---

## 5. 저장 방식

거래 데이터는 다음 파일에 JSONL 형식으로 저장한다.

```text
data/transactions.jsonl
```

카테고리 이름은 거래 데이터와 분리하여 다음 파일에 JSONL 형식으로 저장한다.

```text
data/categories.jsonl
```

한 줄에 거래 하나를 저장한다.

예:

```json
{"id":"TX-000001","type":"expense","date":"2026-09-10","amount":12000,"category":"food","memo":"점심","tags":["meal"]}
{"id":"TX-000002","type":"income","date":"2026-09-10","amount":3000000,"category":"salary","memo":"","tags":[]}
```

카테고리는 한 줄에 하나씩 저장한다.

```json
{"name":"food"}
{"name":"salary"}
```

프로그램 내부 객체와 JSON 데이터 간 변환 기능을 제공한다.

```text
Transaction
    ↓ to_dict
dict
    ↓ json.dumps
JSONL

JSONL
    ↓ json.loads
dict
    ↓ from_dict
Transaction
```

## 6. 구조

기본 구조는 다음과 같다.

```text
budget_app/
├── cli.py
├── models.py
├── repositories.py
├── services.py
└── validators.py
```

책임은 다음과 같이 구분한다.

### models.py

거래 데이터 구조와 직렬화/역직렬화를 담당한다.

주요 구성:

```text
Transaction
Transaction.to_dict()
Transaction.from_dict()
```

### repositories.py

파일 저장과 조회를 담당한다.

주요 인터페이스:

```python
TransactionRepository.add()
TransactionRepository.iter_all()
TransactionRepository.find_by_id()
TransactionRepository.update()
TransactionRepository.delete()
CategoryRepository.add()
CategoryRepository.iter_all()
CategoryRepository.exists()
```

비즈니스 규칙은 처리하지 않는다.

### services.py

거래 기능의 애플리케이션 로직을 담당한다.

주요 인터페이스:

```python
TransactionService.add_transaction()
TransactionService.list_transactions()
TransactionService.update_transaction()
TransactionService.delete_transaction()
TransactionService.list_categories()
TransactionService.is_category_registered()
TransactionService.register_category()
```

ID 생성도 이 계층에서 처리한다.

### validators.py

CLI 입력값을 프로그램에서 사용할 수 있는 값으로 검증 및 변환한다.

예:

```python
parse_date()
parse_amount()
validate_transaction_type()
validate_category_name()
```

### cli.py

사용자 입력과 출력만 담당한다.

흐름:

```text
CLI
 ↓
Service
 ↓
Repository
 ├─ transactions.jsonl
 └─ categories.jsonl
```

## 7. 제너레이터 요구사항

`TransactionRepository`는 거래 전체를 리스트로 반환하지 않는다.

다음 형태의 인터페이스를 사용한다.

```python
def iter_all(self) -> Iterator[Transaction]: ...
```

JSONL 파일을 한 줄씩 읽고 거래 객체를 `yield`한다.

```text
transactions.jsonl
      ↓
한 줄 읽기
      ↓
Transaction 변환
      ↓
yield
```

이를 통해 거래 수가 많아져도 파일 전체를 메모리에 올리지 않는다.

---

## 8. 수정 및 삭제 정책

JSONL은 특정 행을 직접 수정하거나 삭제하기 어렵기 때문에 파일 전체를 다시 작성한다.

기본 흐름:

```text
transactions.jsonl
        ↓
한 줄씩 읽기
        ↓
대상 거래 수정/제외
        ↓
임시 파일 작성
        ↓
기존 파일 교체
```

수정 및 삭제 시 데이터 손상을 줄이기 위해 임시 파일을 사용한다.

---

## 9. 주요 검증 규칙

다음 입력은 유효하지 않은 것으로 처리한다.

### 날짜

```text
2026-13-40
```

→ 올바른 `YYYY-MM-DD` 날짜가 아니므로 거부

### 타입

```text
payment
```

→ `income`, `expense` 이외의 값은 거부

### 금액

```text
0
-1000
abc
```

→ 양의 정수가 아니므로 거부

### ID

수정/삭제 대상 ID가 존재하지 않으면 실패 처리한다.

### 카테고리

거래 추가 시 카테고리 이름은 비어 있을 수 없다.

입력한 카테고리가 `categories.jsonl`에 등록되어 있지 않으면 거래를 바로
저장하지 않는다. 등록된 목록을 안내하고, 새 카테고리 등록 또는 재입력을
선택하도록 한다.

## 10. 완료 조건

다음 명령이 정상 동작하면 이 브랜치의 기능 구현이 완료된 것으로 본다.

```zsh
python -m budget_app add

python -m budget_app list
python -m budget_app list -limit 3

python -m budget_app update \
  -id TX-000001 \
  -amount 15000

python -m budget_app delete \
  -id TX-000001
```

추가로 다음 조건을 만족해야 한다.

- 거래 데이터가 프로그램 종료 후에도 유지된다.
- JSONL 파일을 한 줄씩 읽는다.
- 거래 조회에 제너레이터를 사용한다.
- 존재하지 않는 ID 수정/삭제를 처리한다.
- 잘못된 날짜, 타입, 금액을 저장하지 않는다.
- 거래 추가 시 등록된 카테고리만 사용한다.
- 미등록 카테고리는 안내 후 등록하거나 다시 입력할 수 있다.
- 카테고리 이름은 `categories.jsonl`에 별도로 유지된다.
- CLI, 서비스, 저장소, 모델의 책임이 분리되어 있다.
- 모든 주요 함수와 메서드에 타입 힌트가 적용되어 있다.
