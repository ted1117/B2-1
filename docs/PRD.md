# Lean PRD: 나만의 용돈 기입장

## 1. 목적

파일에 거래를 안전하게 보관하는 Python 콘솔 가계부를 완성한다. 거래 CRUD에
검색, 월별 요약, 카테고리 관리, 예산, CSV 가져오기·내보내기를 더하고,
제너레이터·데코레이터·타입 힌트·모듈 분리의 역할을 설명할 수 있도록 한다.

이 문서는 첨부 과제와 `AGENTS.md`를 기준으로 작성한 전체 요구사항과 기능별
PRD의 진입점이다. 기존 구현의 설명과 앞으로 구현할 요구사항을 구분한다.

## 2. 범위 및 현재 상태

### 포함

- 대화형 거래 추가, 목록, 옵션 기반 수정, ID 기반 삭제
- 기간·카테고리·타입·메모·태그 검색
- 월별 수입·지출·잔액 및 카테고리 지출 TOP N
- 카테고리 추가·목록·삭제, 월 예산 설정 및 요약에서 조회
- UTF-8 CSV 가져오기·내보내기
- JSONL 파일 3개, 저장 경로 설정, 초기 실행 처리
- 스트리밍 조회, 공통 오류 처리 데코레이터, 도움말, 테스트, README

### 제외

백업 명령, 반복 거래, 별도의 표 정렬 기능, GUI, 데이터베이스, 외부 서비스,
카테고리 이름 변경·대체, 별도의 예산 조회 명령은 필수 범위에 추가하지 않는다.
임시 파일과 원자적 교체는 기존 수정·삭제의 안전한 저장 정책으로 유지한다.
여러 프로세스의 동시 쓰기 제어는 이번 과제 범위에 포함하지 않는다.

### 확인한 현재 상태

- 기준 브랜치: `develop`, 기준 커밋: `870c609`
- `feature/transaction`의 거래 CRUD와 기본 카테고리 등록이 반영되어 있다.
- [PRD-001](PRD-001.md)은 기존 거래 기능 명세다.
- 현재 코드는 목록 기본 개수, 저장 경로 옵션, 카테고리 관리 명령, 검색,
  요약, 예산, CSV 기능, 공통 데코레이터를 아직 제공하지 않는다.
- 현재 기본 테스트 29개 통과는 거래 기능의 검증 결과이며 전체 과제 완료를
  의미하지 않는다. 신규 PRD는 모두 **계획 / 구현 미착수**다.

테스트·README·진행 상태는 해당 기능 브랜치에서 함께 갱신한다.

## 4. 공통 기술 기준

- Python 3.12, `uv` 사용. 애플리케이션은 표준 라이브러리만 사용한다.
- 외부 런타임 의존성을 추가하지 않는다. Ruff는 저장소 지침의 개발 검사
  도구로만 사용하고, 테스트는 표준 라이브러리 `unittest`로 작성한다.
- 실행 진입점은 `python -m budget_app <command>`다.
- `Transaction` dataclass를 유지하고 클래스 2개 이상, 모듈 3개 이상으로
  책임을 구분한다. 기존 `cli.py`, `models.py`, `repositories.py`,
  `services.py`, `validators.py`를 확장하고 필요한 데코레이터 모듈만 추가한다.
- 함수·메서드의 인자와 반환값, 가능한 클래스 속성에 타입을 명시한다.
  Python 3.12 기본 제네릭 문법을 사용하고 `Any`는 필요한 경우로 제한한다.
- CLI는 입력·출력, 서비스는 업무 규칙, 저장소는 파일 I/O, 모델은 데이터,
  검증 함수는 변환·유효성 검사를 담당한다.

## 5. CLI 표기 확인 사항

**사용자 확인 대기:** 과제 상세 요구사항과 기존 PRD-001·코드는 `--limit`,
`--help` 같은 이중 하이픈을 사용하지만, 과제 제약사항과 `AGENTS.md`는
단일 하이픈 `-`로 통일하도록 지시한다. 적용 우선순위는 사용자 확인 후
확정한다. 확인 전에는 기존 CLI를 변경하지 않는다.

새 PRD에서는 옵션의 이름과 필수 여부를 먼저 정의한다. 아래와 개별 PRD의
실행 예시는 기존 PRD-001과 과제 상세 설명의 `--`를 사용한 **초안**이며,
접두사 정책의 확정을 의미하지 않는다. 확인 후 모든 예시와 구현 기준에 같은
접두사를 반영한다. 이 확인 사항이 남아 있는 동안 CLI 표기 변경은 착수하지 않는다.

## 6. 사용자 흐름과 공통 정책

| 명령 | 입력 방식·필수 입력 | 결과 |
| --- | --- | --- |
| `add` | 날짜·타입·카테고리·금액·메모·태그 대화형 | 저장 성공 및 생성 ID |
| `list` | `limit` 선택, 기본 20 | 최근 등록한 거래부터 최대 N개 |
| `update` | `id` 필수, 수정 필드 옵션 | 지정한 필드만 수정 |
| `delete` | `id` 필수 | 삭제 성공 또는 없는 ID 오류 |
| `category add/list/remove` | 추가·삭제 이름은 대화형 | 등록·목록·삭제 결과 |
| `search` | `from`, `to`, `category`, `type`, `q`, `tag` | 조건을 모두 만족하는 거래 |
| `summary` | `month` 필수, `top` 기본 3 | 월별 합계·TOP N·설정된 예산 |
| `budget set` | `month`, `amount` 필수 | 해당 월 예산 저장 |
| `import` | `from` CSV 경로 필수 | 새 거래 등록 및 처리 건수 |
| `export` | `out` 필수, `month` 또는 `from`·`to` 필수 | CSV 생성 및 처리 건수 |

- 기본 저장 폴더는 실행 위치의 `./data`다. 전역 `data-dir` 옵션은 하위
  명령 앞에 지정하며 세 JSONL 파일에 일괄 적용한다.
- 도움말은 최상위·각 명령·중첩 명령에서 제공하고 정상 종료한다.
- 최초 실행에는 저장 폴더와 없는 파일을 만든다. 도움말은 파일을 만들지 않는다.
- 초기 카테고리는 과제의 **안 B**를 선택한다. 빈 목록에서는 `category add`를
  안내하고 `add`를 종료한다. 목록이 생긴 후에는 기존 `add`의 미등록 카테고리
  등록·재입력 흐름을 유지한다. 이 부분은 PRD-001의 빈 목록 동작을 보완한다.
- 최신순은 기존 구현에 맞춰 **등록 순서의 역순**으로 정의한다. 거래 날짜를
  과거로 입력해도 방금 등록한 거래가 먼저 나온다. 수정은 저장 위치를 바꾸지
  않고, CSV 등록은 CSV 행 순서대로 추가한다. 날짜는 검색·월별 집계 기준이다.
- 날짜 범위의 양 끝을 포함한다. 여러 검색 조건은 AND로 결합한다.
- 저장된 거래의 ID는 서로 유일하다. 기존 `TX-000001` 형식과 생성 방식을
  유지하며, 삭제 이력 추적이나 가져오기 중복 내용 판별은 추가하지 않는다.

## 7. 데이터와 저장 계약

| 파일 | 한 줄의 JSON 객체 | 규칙 |
| --- | --- | --- |
| `transactions.jsonl` | `id`, `type`, `date`, `amount`, `category`, `memo`, `tags` | 거래 한 건 |
| `categories.jsonl` | `name` | 카테고리 한 개, 이름 중복 금지 |
| `budgets.jsonl` | `month`, `amount` | 월당 예산 한 개 |

- 모든 파일은 UTF-8 JSONL이다. 거래일은 `YYYY-MM-DD`, 예산 월은 `YYYY-MM`로
  저장한다. 내부 거래일은 `datetime.date`, 금액은 양수 정수다.
- 타입은 `income` 또는 `expense`다. 거래의 카테고리는 반드시 등록되어야 한다.
  메모는 기본 빈 문자열, 태그는 기본 빈 목록이다.
- 카테고리와 입력 태그는 앞뒤 공백을 제거한다. 빈 카테고리는 거부하고 빈
  태그 조각은 제외한다. 카테고리·태그의 대소문자는 구분한다.
- JSONL은 한 줄씩 해석하고 제너레이터로 전달한다. 빈 줄은 건너뛰지만 손상된
  JSON이나 필수 필드 오류를 조용히 무시하지 않는다.
- 수정·삭제·예산 덮어쓰기·가져오기는 같은 디렉터리에 임시 파일을 작성하고
  성공한 경우에만 원본을 교체한다. 실패하면 원본을 유지하고 임시 파일을 정리한다.
- `list`는 최대 N개만 보관하고, 전체 검색은 역방향 블록 읽기 등의 방식으로
  결과 전체를 메모리에 모으지 않는다. 요약은 카테고리별 합계만 보관한다.

CSV는 영구 저장 형식과 별개인 교환 형식이다. 아래 6개 열 순서로 내보내며,
가져오기는 필수 4개 열을 요구하고 선택 열의 생략을 허용한다.

| 열 | 필수 | 값 |
| --- | --- | --- |
| `date` | Y | `YYYY-MM-DD` 실제 날짜 |
| `type` | Y | `income` / `expense` |
| `category` | Y | 등록된 카테고리 |
| `amount` | Y | 양수 정수 |
| `memo` | N | 문자열, 생략 시 빈 문자열 |
| `tags` | N | 쉼표로 구분한 문자열, 생략 시 빈 목록 |

CSV는 UTF-8·헤더 포함이며 `id`를 교환하지 않는다. 세부 오류·인용·등록 정책은
[PRD-007](PRD-007.md)에서 정의한다.

## 8. 오류 처리

- 입력 오류·없는 ID·미등록 카테고리·잘못된 옵션·파일 오류를 원인과 해결
  힌트로 표준 오류에 출력한다. 스택트레이스를 출력하지 않는다.
- 정상 처리, 도움말, 조회 결과 없음은 종료 코드 0이다. 실패·입력 중단은
  0이 아닌 코드다. 잘못된 입력을 다시 받아 성공한 경우는 정상 처리다.
- JSONL/CSV 오류는 가능한 경우 파일 경로와 행 번호를 제공한다.
- 공통 오류 처리 데코레이터를 직접 구현해 명령 실행에 실제 적용한다.
  자세한 책임과 검증은 [PRD-002](PRD-002.md)를 따른다.

## 10. 원문에서 정하지 않은 정책의 보완

기본 목록 20개, TOP 3, 등록 역순, 빈 카테고리 안 B, 사용 중 카테고리 삭제
차단, 월·날짜 범위의 동시 지정 거부, CSV 전체 성공 또는 전체 실패는 구현을
명확하게 하기 위해 이 PRD에서 선택한 정책이다. 과제 원문의 고정값으로
취급하지 않는다. 추가적인 요구사항·엣지 케이스는 구현 전에 해당 기능 PRD에
보완하고, 사용자 지시와 충돌하면 우선순위를 확인한다.
