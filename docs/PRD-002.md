# Lean PRD: 공통 CLI 및 실행 기반 보완

- 브랜치: `feature/cli-foundation`
- 상태: 구현 완료
- 선행 작업: [PRD-001](PRD-001.md)
- 공통 기준: [전체 PRD](PRD.md)

## 1. 목적

기존 거래 CLI에 저장 경로·최초 실행·기본 조회 개수·공통 오류 처리를 보완한다.
이후 추가되는 모든 명령이 같은 실행 규칙을 따르도록 한다.

## 2. 범위

### 포함

- 전체 CLI의 확정된 옵션 표기와 도움말
- 전역 `data-dir` 옵션과 JSONL 파일 3개 초기화
- `list` 기본 조회 개수와 제한된 메모리 사용
- 명령 실행에 적용하는 공통 오류 처리 데코레이터
- 오류 원인·해결 힌트·종료 코드, 저장 파일 형식 오류 처리
- 기존 CRUD 회귀 확인 및 README의 실행·저장 안내

### 제외

검색·집계·카테고리 관리·예산·CSV 업무 기능, 로그 및 실행 시간 측정,
새 저장 형식, 기존 CRUD의 전면 재구성은 포함하지 않는다.

## 3. 사용자 시나리오

옵션 접두사는 [전체 PRD의 CLI 표기](PRD.md#5-cli-표기)를 따른다.

```text
python -m budget_app -help
python -m budget_app list -help
python -m budget_app -data-dir ./my-data list
python -m budget_app list -limit 3
```

- `data-dir` 기본값은 실행 위치 기준 `./data`다. 위치는 하위 명령 앞이다.
- 최초 유효한 명령 실행 시 디렉터리와 없는 `transactions.jsonl`,
  `categories.jsonl`, `budgets.jsonl`을 빈 파일로 만든다. 기존 내용은 유지한다.
- 잘못된 옵션이나 도움말 요청만으로 저장 파일을 생성하지 않는다.
- 빈 카테고리 안내 및 `add` 진입 차단은 PRD-003에서 연결한다.
- `list`는 `limit` 생략 시 20개, 지정 시 양수 정수 N개까지 출력한다.
  등록 역순으로 출력하고, 비어 있으면 `데이터 없음`과 종료 코드 0을 반환한다.

## 4. 구조와 저장 정책

기존 모듈 책임을 유지한다. CLI에서 선택한 경로를 저장소 생성 시 전달하고
거래·카테고리 경로에 같은 디렉터리를 적용한다. 예산 파일의 생성만 이 PRD가
담당하며 예산 데이터 읽기·쓰기는 PRD-006에서 구현한다.

`list`는 `iter_all()`을 소비하면서 크기 N의 `deque` 등 제한된 버퍼를 사용한다.
기본 실행에서 무제한 `deque`, `list()` 또는 전체 정렬로 모든 거래를 보관하지
않는다. 저장 위치와 순서는 바꾸지 않는다.

## 5. 데코레이터 및 오류 계약

공통 예외 처리 데코레이터를 `decorators.py` 등에 한 개 구현하고 실제 명령
실행 함수에 적용한다. `functools.wraps`를 사용하고 함수 타입 힌트를 작성한다.
명령 내부의 제너레이터 순회가 끝날 때까지 적용 범위에 포함한다.

- 입력 검증 오류: 잘못된 값의 원인과 허용 형식·예시를 출력한다.
- 없는 ID: 수정·삭제 실패와 ID를 확인할 `list` 명령을 안내한다.
- 파일 I/O 오류: 대상 경로와 경로·권한 확인 힌트를 출력한다.
- JSONL 손상: 잘못된 JSON, 필수 키 누락, 잘못된 필드 타입·값을 경로와 행
  번호를 포함한 오류로 변환한다. 빈 줄은 건너뛴다.
- 표준 라이브러리 파서의 인자 오류에도 원인과 도움말 안내를 제공한다.
- `EOFError`, `KeyboardInterrupt`로 입력이 중단되면 중단 메시지를 출력하고
  0이 아닌 코드로 종료한다. 완료되지 않은 거래는 저장하지 않는다.
- 실패 시 원본 파일을 가능한 성공 데이터로 덮어쓰지 않는다. 기존 거래
  수정·삭제의 임시 파일 정리와 원자 교체 동작을 유지한다.

정상·도움말·결과 없음은 0, 잘못된 옵션은 2, 그 외 처리 오류·입력 중단은 1로
정한다. 오류는 표준 오류로 출력하며 스택트레이스를 노출하지 않는다.

## 6. 검증 및 완료 조건

표준 라이브러리 `unittest`와 임시 디렉터리로 다음을 확인한다.

- [x] 빈 경로에서 명령을 실행하면 3개 파일이 생성되고 재실행 시 내용이 유지된다.
- [x] 사용자 지정 경로만 사용하며 기본 `data`의 파일과 섞이지 않는다.
- [x] 도움말과 인자 오류는 파일을 생성하지 않는다.
- [x] 최상위·CRUD 및 이후 중첩 명령에 도움말을 적용할 공통 방식이 있다.
- [x] 거래 25건에서 기본 목록은 마지막 등록 20건, `limit=3`은 마지막 3건이다.
- [x] `limit`의 0·음수·비정수는 원인·힌트와 비정상 코드로 끝난다.
- [x] 빈 목록은 `데이터 없음`을 출력하고 정상 종료한다.
- [x] 잘못된 JSON·필드 누락·타입 오류·파일 접근 실패에 스택트레이스가 없다.
- [x] 명령이 순회하는 제너레이터에서 발생한 오류도 데코레이터가 처리한다.
- [x] 기존 거래 추가·조회·수정·삭제 및 임시 파일 실패 시 원본 보존이 유지된다.
- [x] README에 실행·저장 경로·파일 형식을 기재하고 전체 테스트·Ruff가 통과한다.

## 7. 구현 순서

1. CLI 옵션 표기 확인 결과를 문서·도움말·기존 테스트에 반영한다.
2. 저장 경로 전달과 초기화를 연결한다.
3. 목록 기본값·빈 결과 처리를 보완한다.
4. 공통 오류 타입·메시지와 데코레이터를 연결한다.
5. 관련 테스트·전체 테스트·Ruff를 실행하고 README·PROGRESS를 갱신한다.
