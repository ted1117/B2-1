# Lean PRD: CSV 가져오기 및 내보내기

- 브랜치: `feature/csv-import-export`
- 상태: 계획 / 구현 미착수
- 선행 작업: [PRD-003](PRD-003.md), [PRD-004](PRD-004.md)
- 공통 기준: [전체 PRD](PRD.md), [오류 처리](PRD-002.md)

## 1. 목적

외부 CSV로 거래를 등록하고 선택한 기간의 거래를 CSV로 내보낸다. 실패한
가져오기로 기존 거래가 손상되거나 일부만 반영되는 일을 방지한다.

## 2. 범위

### 포함

- `import`, `export` 명령과 UTF-8 CSV 스키마
- 전체 검증 후 일괄 반영하는 가져오기
- 월 또는 날짜 범위로 필터링하는 내보내기
- 처리 건수·입출력 오류·원본 보존 검증

### 제외

Excel 파일, JSON 내보내기, 기존 거래 덮어쓰기, 자동 카테고리 등록,
내용 기반 중복 제거, 실패 행 건너뛰기 모드는 추가하지 않는다.

## 3. 사용자 시나리오

```text
python -m budget_app import --from import.csv
python -m budget_app export --out september.csv --month 2026-09
python -m budget_app export --out range.csv --from 2026-09-01 --to 2026-09-15
```

옵션 접두사는 [공통 확인 사항](PRD.md#5-cli-표기-확인-사항)을 따른다.
`import`의 `from`은 입력 파일 경로이며 `export`의 `from`은 시작 날짜다.

- 가져오기 성공: `[완료] imported=5, skipped=0`처럼 등록 건수를 출력한다.
- 내보내기 성공: 출력 경로와 기록 건수를 출력한다.
- 결과가 없으면 헤더만 내보내고 0건으로 정상 종료한다.

## 4. CSV 계약

표준 라이브러리 `csv.DictReader`·`csv.DictWriter`를 사용하고 파일을
`encoding="utf-8"`, `newline=""`로 연다. 입력은 `strict=True` 등 엄격한
해석을 사용해 닫히지 않은 따옴표 등의 CSV 구문 오류를 거부한다.
내보내기 열 순서는 다음으로 고정한다.

```csv
date,type,category,amount,memo,tags
2026-09-13,expense,food,12000,점심,"meal,work"
2026-09-13,income,salary,3000000,,
```

| 열 | 필수 | 검증 및 기본값 |
| --- | --- | --- |
| `date` | Y | `YYYY-MM-DD` 실제 날짜 |
| `type` | Y | `income` / `expense` |
| `category` | Y | 앞뒤 공백 제거 후 등록된 이름 |
| `amount` | Y | 양수 정수, 0·음수·소수 거부 |
| `memo` | N | 생략 시 빈 문자열 |
| `tags` | N | 쉼표 분리·앞뒤 공백 제거·빈 조각 제외 |

가져오기에서는 열 순서가 달라도 헤더 이름으로 읽는다. 필수 4개 열은 모두
필요하고 선택 열의 생략은 허용한다. 중복 헤더·알 수 없는 열·열 수 불일치는
오류로 처리한다. 헤더 없는 빈 파일은 오류, 유효한 헤더만 있는 파일은 0건 성공이다.

메모의 쉼표·따옴표·줄바꿈과 한글은 CSV 인용 규칙으로 보존한다. `tags`는 하나의
CSV 필드 안에서 쉼표로 구분하므로 필요한 경우 해당 필드 전체를 인용한다.
태그 이름 자체에 쉼표를 포함하는 형식은 지원하지 않는다.

`id`는 CSV 열에 포함하지 않으며 가져오는 모든 행에 새 ID를 발급한다.
동일 내용의 CSV를 다시 가져오면 새 거래로 다시 등록된다. 이를 README에 명시한다.

## 5. 가져오기와 저장 정책

가져오기는 **전체 성공 또는 전체 실패**로 고정한다. 원문이 행 오류 처리
방식을 지정하지 않아 데이터 안전성을 위해 선택한 정책이다.

1. 기존 거래를 스트리밍으로 읽어 임시 파일에 복사하고 현재 최대 ID를 파악한다.
2. CSV를 행 단위로 읽어 검증하고, 등록 카테고리를 확인한다.
3. 파일 안의 순서대로 충돌하지 않는 새 ID를 부여해 임시 파일에 기록한다.
4. 전체 파일의 검증과 쓰기가 성공하면 거래 JSONL을 원자적으로 교체한다.
5. 실패하면 임시 파일을 삭제하고 기존 거래·카테고리·예산 내용을 유지한다.

미등록 카테고리는 자동 생성하지 않고 `category add` 후 다시 가져오도록 안내한다.
실패 시 `imported=0`과 원인·입력 파일 경로·가능한 행 번호를 출력하고 비정상
종료한다. 일부 행만 성공 처리하거나 성공 건수를 출력하지 않는다. CSV 또는
기존 거래 전체를 메모리에 보관하지 않는다.

## 6. 내보내기 정책

- `out` 경로는 필수다.
- `month` 단독 또는 `from`과 `to` 쌍 중 정확히 하나를 지정해야 한다.
  조건 없음, 월과 날짜 범위 혼용, 범위 한쪽만 지정은 오류다.
- 월은 `YYYY-MM`, 날짜는 `YYYY-MM-DD`를 검증한다. 역전 범위는 거부한다.
- 월의 첫날·마지막 날 또는 지정한 범위 양 끝을 포함한다.
- 거래는 검색과 같은 등록 역순으로 순회하며 한 행씩 CSV로 기록한다.
- 출력 경로에 파일이 있으면 오류로 종료하고 다른 이름을 안내한다. 자동
  덮어쓰기 옵션은 추가하지 않는다. 따라서 기존 데이터 파일도 덮어쓰지 않는다.
- 출력 폴더가 없거나 쓸 수 없으면 폴더·권한 확인 힌트를 출력한다.
- 출력 폴더의 임시 파일을 사용하고 성공 시에만 최종 파일로 확정한다.
  실패한 임시 파일은 정리하고 성공으로 보고하지 않는다.

## 7. 구조

CLI는 인자와 결과 메시지, 서비스는 검증·ID 발급·필터 조건, 저장소는 임시
파일과 JSONL 반영을 담당한다. CSV 변환은 표준 `csv`로 분리하되 기존 모듈
구조를 우선하고 별도의 프레임워크·범용 저장소 계층을 추가하지 않는다.

## 8. 완료 조건

- [ ] 정상 CSV 5건을 등록하면 새 ID 5개와 `imported=5, skipped=0`이 확인된다.
- [ ] 선택 열 생략·열 순서 변경·헤더만 있는 입력을 처리한다.
- [ ] 필수 열 누락·중복/알 수 없는 헤더·잘못된 열 수·날짜·금액·타입을 거부한다.
- [ ] 닫히지 않은 따옴표 등 손상된 CSV 구문을 오류로 처리하고 원본을 보존한다.
- [ ] CSV 뒤쪽 행이 잘못되어도 이전 거래 파일이 바이트 단위로 동일하다.
- [ ] 미등록 카테고리는 등록되지 않고 전체 가져오기가 실패한다.
- [ ] ID가 저장된 거래 및 이번 가져오기 행 사이에서 중복되지 않는다.
- [ ] 한글·메모의 쉼표/따옴표/줄바꿈·다중 태그가 CSV 왕복 후 보존된다.
- [ ] 월·날짜 경계와 최신순, 조건 없음·혼용·단일 경계 오류가 검증된다.
- [ ] 대상 없음은 헤더만 생성하고 0건으로 성공한다.
- [ ] 기존 출력 파일·없는 입력 파일·파일 쓰기 실패에 원인·힌트와 비정상 코드가 나온다.
- [ ] 가져오기·내보내기 실패 시 원본과 기존 출력 파일을 유지하고 임시 파일을 정리한다.
- [ ] `unittest`에서 임시 경로를 사용하고 실제 사용자 데이터는 변경하지 않는다.
- [ ] README의 스키마·예시·중복/실패 정책을 작성하고 전체 테스트·Ruff가 통과한다.

## 9. 구현 순서

1. CSV 헤더·필드 검증과 직렬화를 작성한다.
2. 스트리밍 임시 파일 기반 일괄 등록을 구현한다.
3. 날짜 필터와 CSV 내보내기를 연결한다.
4. 왕복·전체 실패·파일 실패 사례를 검증한다.
5. 전체 검사 후 README·PROGRESS를 갱신한다.
